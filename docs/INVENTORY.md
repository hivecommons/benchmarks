# Benchmark data inventory — what hive already collects

Read from the `hivecommons/hive` source tree (local clone, 2026-11-11). Goal: decide what
`hivecommons/benchmarks` can publish today with zero new telemetry, and what the hive
exporter (RFC) has to add.

## TL;DR

* **The per-PR evidence bundle (`pkg/evidence.Bundle`) is the benchmark record.** It already
  carries author agent/backend/model, ACMM level, per-perspective reviewer verdicts with model +
  backend, CI status at head, merge event, reverts/follow-ups, issue reopens, and time-to-merge.
  Everything a leaderboard needs except cost and sandbox runtime is in there.
* **Hive already publishes a monthly benchmark** — `src/docs/benchmarks/outcomes-YYYY-MM.json`
  (+ `.md`, cost, stories, red-team JSON), generated by `hivectl evidence benchmark` via
  `src/scripts/outcome-benchmark.sh` (`pkg/outcomebench`). It compares *mediated vs unmediated*
  PRs. It is **not** split per model / harness / runtime — that is the gap this repo fills.
* **Cost is per agent and per model, not per PR.** `GET /api/cost` (pkg/tokens collector) buckets
  tokens by agent, by model, by session; `GET /api/repo-cost` joins to repos by time interval
  (phase-3 interval join). Cost-per-merged-PR exists only as a fleet ratio.
* **ACMM is a repo/hive maturity score, not an agent score.** `GET /api/acmm/evaluation` scores
  the *repository's* automation maturity (criteria files present, operational level). It is a
  context dimension for a result ("this ran at ACMM L3"), not a quality metric of the agent.
* **Hub already aggregates across hosted hives**: `/api/fleet-stats`, `/api/hub/stats`,
  `/api/hub/evidence` (+ `/report`), `/api/hub/leaderboard`. Spokes heartbeat evidence summaries
  (calibration buckets, merged/reverted 90d, reviewer/author model *families*, time-to-merge
  medians). Nothing per hive is public today; hub evidence needs an admin session.
* **Missing today**: sandbox runtime on the record, per-PR cost attribution, task kind
  (issue-fix / pr-review / ci-repair…), human-intervention count, retries, CI-green-on-first-push,
  and any opt-in/consent flag. These are the exporter's job.

## Enumerations hive already uses (schema should reuse them)

* **Harness / CLI backend** (`crux/config`, `IsCLIBackend`): `agy aider bob claude cline codex copilot gemini goose kilo muse omnigent omp opencode openhands pi`. Inference backends (`litellm vllm watsonx …`) are separate.
* **Sandbox runtime** (`crux/config/agent_config.go`): `podman`, `job` (Kubernetes Job), `openshell`; plus `none` (in-process). "substrate" is not a hive runtime value today — keep it as an open enum.
* **Author kind**: `human | agent | bot`.
* **Review verdict**: `approve | changes_requested | comment` (+ confidence 0–1).
* **ACMM level**: 0–5 (ADR-0003).
* **Model family** (`pkg/modelfamily`): normalised vendor family for exact model names.

## What a per-run benchmark record can be filled from today (no code change)

| Schema field | Source |
|---|---|
| `agent.name`, `agent.harness` | `bundle.author.agent`, `bundle.author.backend` |
| `model.name` | `bundle.author.model` (exact); `model.provider` via `modelfamily` |
| `task.repo` | `bundle.repo` (consent-gated) |
| `outcome.pr_opened/pr_merged` | `bundle.outcome.state`, `bundle.merge` |
| `outcome.ci_green_first_try` | first bundle for the PR (`previous_bundle_id == ""`) with `ci.status == success` |
| `outcome.review_verdict` | worst verdict over `bundle.verdicts[]` on the merged head |
| `outcome.human_interventions` | `len(bundle.human_actions)` |
| `outcome.wall_clock_s` | `merge.at − merge.opened_at` |
| `outcome.retries` | count of bundles chained by `previous_bundle_id` |
| `quality.reverted`, `quality.followed_up` | `reverted_by`, `followed_up_by` |
| `quality.acmm_level` | `bundle.policy.acmm_level` |
| `cost.*` | **not per PR** — only per agent/model from `/api/cost`; exporter must apportion or publish per-model unit cost instead |
| `sandbox_runtime` | **not recorded in bundle** — exporter must stamp it from the agent config at kick time |
| `task.kind` | **not recorded** — derivable from agent role (`review` agents → `pr-review`, fix agents → `issue-fix`) |

## Existing docs / proposals

* `src/docs/benchmarks/README.md`, `monthly-automation.md` — the only benchmark publication; explicitly "supplied-input publication cadence, not a deployed data collector".
* ADR-0003 (ACMM levels), ADR-0014 (hub–spoke), ADR-0007 (token mint). No ADR/RFC proposes a cross-hive, per-model public leaderboard.
* `docs/landscape.md`, `what-is-hive.md` mention "leaderboard" only in the contributor-leaderboard sense (`/leaderboard`).
* Open issues matching "benchmark": only #17620 (workflow models RFC) — unrelated.
* No `hivecommons/benchmarks`, `agent-benchmarks` or `leaderboard` repo existed before this work.

## Privacy rules proposed for publication (feeds RFC + GOVERNANCE.md)

1. Default **opt-in per hive** (`benchmarks.publish: true` in hive.yaml, default false).
2. Repo names published only when `task.repo_consent: true` (public repo **and** owner opted in); otherwise `task.repo` is omitted and `task.repo_visibility` kept.
3. Never export: GitHub logins, finding summaries/paths, prompts, session IDs, Nous questions, absolute per-hive USD unless `cost_consent`.
4. Aggregates follow the outcomebench rule: n and Wilson 95% interval or not reported; n < 10 suppressed.
5. Records carry `source.hive_id` as a salted hash unless the owner opts to be named.
