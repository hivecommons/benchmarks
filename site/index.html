Methodology

How these numbers are computed
  • Models. Each CLI spells a model its own way (claude-sonnet-5-5 from Copilot CLI, claude-sonnet-5.5 from Claude Code, openai-codex/gpt-6.1-sol from pi). Rows are keyed by the canonical id — lowercase, CLI/gateway prefix and reasoning-effort suffix stripped, version separators as dots — computed by hive's exporter (model.canonical) and re-derived at index build for older records (scripts/modelid.py). The vendor shown is the model family's, never the CLI. auto is a runtime auto-select whose model the hive was not told. Hover a model for the raw ids; “Split by runtime/CLI” breaks each model out per harness.
  • Unit. One record = one unit of agent work on one pull request, exported from a hive's signed per-PR evidence bundle: agent-authored (the agent opened the PR) or agent review (the swarm reviewed someone's PR; the model shown is the majority reviewer model). Schema: schema/result.schema.json.
  • Backfill. Records with exporter: backfill-from-cluster were converted from existing evidence by scripts/convert-evidence.py; sandbox_runtime: none because those hives ran agents in-process. task.kind is unknown unless the agent name says otherwise.
  • Median time to merge is read from a 12-bucket log-scale histogram, so it is a bucket midpoint, not an exact value.
  • Merge rate = merged ÷ records with pr_opened. CI green first try = ci_green_first_try true ÷ records where CI was captured (nulls excluded). Cost / merged PR (shown with its coverage: records with cost ÷ all records) = Σ cost.usd_est over merged PRs in the group ÷ merged PRs with a cost estimate; cost.basis = unknown records are excluded from the numerator and the denominator. The small "attr." percentage says how many of the group's records have a PR-attributed cost rather than a fleet-median imputation.
  • Intervals. Every rate shows n and a 95% Wilson score interval. Rates with n < 10, and cost per merged PR with fewer than 30 merged PRs with a cost estimate, are shown as insufficient data; the rate rule is the same hivecommons/hive uses for its monthly outcome benchmark.
  • Cost basis — every dollar figure is an estimate, not a bill. Each record carries cost.usd_est and cost.basis:
    • reported — the harness or gateway returned a billed figure (OpenRouter/LiteLLM). None yet.
    • tokens_x_pricing — hive's token collector counts input/output/cache tokens per agent kick and prices them with the same list-price table its dashboard Cost panel uses (schema/pricing.json, mirrored from hive/src/pkg/tokens/pricing.go). Spend is attributed to a PR through hive's launch attribution (/api/launch-cost): the kick that named the issue(s) the PR closed, or the PR itself for review-swarm kicks; a kick naming several refs is split evenly. Subscription plans (Claude Max, Copilot premium requests) and self-hosted inference do not bill at list price, so this is an order-of-magnitude proxy.
    • fleet_model_median — the PR has no attributed kick (older than the attribution store, kicked without a ref, or usage outside the 6-hour ownership horizon). It gets the median tokens_x_pricing cost of attributed PRs for the same model and role across the whole fleet (≥5 samples), else the fleet's median token mix for the role priced at that model's list price. Imputed at index-build time; the raw record stays unknown.
    • unknown — nothing available; excluded from all cost aggregates. Tiles say "n=… with cost data".
    Why not duration × $/h? wall_clock_s is PR open→merge time, not agent runtime, so it would mostly measure review latency.
  • Synthetic records (synthetic: true) are excluded unless you tick the box. They exist so the page renders before real exports land.
  • Privacy. Every hive publishes anonymized records by default (opt-out: benchmarks.publish: false). Repository names appear only for public repositories (activity on a public repo is already public; the exporter sets repo_consent for repos GitHub reports as public). Private repos never appear, and an owner can opt out of naming with benchmarks.repo_consent: false. No logins, prompts, finding text or code are published. See GOVERNANCE.md.
  • Canonical task kinds. The leaderboard covers issue-fix, ci-repair, pr-review and dependency-update. size.bucket (xs to xl) is required for issue-fix and optional for the others. Records of other kinds are stored but not ranked.
  • Metrics. Primary: merge rate, CI green first try, cost per merged PR, 14-day revert rate. Secondary: median time to merge, human interventions per record, retries. Cost per merged PR excludes records without cost from both numerator and denominator and always shows coverage next to it.
  • Hive identity. Hives are keyed by a stable salted hash so trends work; a hive may ask for its salt to be rotated, which starts a new, unlinked series.
  • Synthetic and replay results need an explicit synthetic: true, are never mixed into the default leaderboard and are shown only when you tick "Include synthetic".
  • Full text. METHODOLOGY.md is the authoritative version.
  • Confounders. Models are not assigned to tasks at random: harder tasks go to bigger models, review agents never open PRs, and hives differ in ACMM policy. Filter by task kind and ACMM level before comparing; treat cross-model differences as observational. See the known limitations in METHODOLOGY.md.
